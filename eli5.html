02

文件是按列保存的同一张样本表

先理解“每行对齐”，就能理解字段形状、身份列和时间构造。

HDF5：数组与标量共存

Flt2005_train.h5
├── line       [2004.0, 2004.0, 2004.0]
├── tt         [54616.0, 54616.1, 55252.0]
├── mag_1_uc   [10.0,    11.0,    12.0]
├── …          每个样本字段形状为 (N,)
├── N          3        ← 标量
├── dt         0.1      ← 标量
└── info       "…"      ← 标量

上述三行来自测试用合成文件，不是真实航次的完整数据。HDF5 可以看成一个容纳命名数组的文件容器。

输出：一个样本对应一行

源行linettmag_1_uc
02004.0054616.010.0
12004.0054616.111.0
22004.0055252.012.0

同一个行下标在各数组中指向同一个样本。因此 line 与 tt 必须同为一维、长度相同；已知样本字段存在时也必须具有这个长度。

N、dt、info 是整份文件的说明，不能作为 read 的逐行数据列。

标准化读取总是先给出六列身份信息

列类型来源与处理
flightint64优先读取源字段；缺少时使用 FileSpec.flight；已有值必须与目标航次一致。
linepandas string必须存在、有限且非负；数值标签格式化为两位小数字符串。
yearint64优先读取源字段；缺少时从目录日期取年份。
doyint64年内日序，从 1 开始；缺少时取目录日期的日序，已有值按闰年检查。
ttfloat64必须存在且为有限实数，表示源时间的午夜后秒数。
timedatetime64[ns, UTC]根据 year、doy 与 tt 计算的绝对时间。
time = 当年 1 月 1 日 UTC + (doy − 1) 天 + tt 秒
2020 / doy 172 / tt 45100 → 2020-06-20 12:31:40 UTC

缺省值只补缺失字段；已有但损坏的身份数据会报错。实现检查 tt 为有限实数，没有额外把它限制在 [0, 86400) 内。源 year、doy 验证整数与日历有效性，并不会强制等于目录日期。

dt、tt_range 和文档段落，为什么不能证明数据连续？

dt 只是文件声明的采样间隔；tt_range 只是实际最小值与最大值，两端都是观测值。两者都没有逐个验证相邻样本间隔。读取器也不会排序、补齐时间缺口、插值或重采样。

segments() 的起止时间来自来源文档，保留原值；它们既不自动转成 Selection，也不参与读取掩码。因此，文件名的 _train 或目录中的 is_holdout 均不会自动决定返回哪些行。

04

Selection：先让输入只有一种解释

构造对象时验证与规范化；读取时只执行已经明确的约束。

航线：标签统一，顺序不重排

["2005.2", "2005.20"]→("2005.20",)

canonical_line 先用正则限制十进制字符串，再用 Decimal 格式化为两位小数。_normalise_lines 按首次出现顺序去重。

输入浮点数、负号、通配符、范围表达式或超过两位小数都会被拒绝。多个标签表达“属于其中任意一个”，不会按标签列表顺序重新排列源文件。

源文件中的 line 则通过浮点数格式化。两条路径共享两位小数的输出形式，但读取器不会额外检查源数值原本是否最多两位小数。

时间：左闭右开，允许单边

start ≤ value < stop

slice(10, 20) 保留 10，排除 20。slice(None, 20) 仅限制上界；slice(10, None) 仅限制下界。

拒绝任何显式步长、两个空边界、倒置区间与无效时间。tt 的边界是有限实数；time 的边界转换为 UTC Timestamp，无时区输入按 UTC 理解。

tt 与 time 二选一；lines 可与它们组合，最终取交集。

输入规则背后的共同原则：确定且有序

输入代码中的处理为什么这样处理
flightflight_id 接受正整数 Integral；排除 bool。Python 中 bool 也是整数子类，需显式排除；允许 NumPy 整数。
生成器、list、tuple、Series、数组ordered_values 消费一次，得到 tuple。固定后续迭代结果，避免生成器读过即空。
set、dict、字符串作为序列容器通用序列验证拒绝；单个合法字符串由上层单独处理。避免集合无序、映射含义不明，或把字符串拆成字符。
重复 flights / columns / linesdict.fromkeys 按首次出现保留一个。不重复准备文件或输出同名列。
重复 Selection保留完整序列。不同查询的结果属于调用者明确要求，允许重复样本。
为什么 frozen 对象还能在 __post_init__ 里写属性？

@dataclass(frozen=True, slots=True) 自动生成构造函数等方法，并限制常规属性赋值；KW_ONLY 使 lines、tt、time 必须使用关键字。构造后调用的 __post_init__ 使用 object.__setattr__ 一次性写入规范化结果，这是内部初始化步骤。

对象建好之后，正常赋值会抛出 FrozenInstanceError。Selection.all(flight) 只是 cls(flight) 的便捷写法，并没有另一套读取逻辑。

源码：selection.py · canonical_line（L18）、_normalise_range（L40）、Selection（L86）；_validation.py。

05

reader：把明确的条件变成真实行

理解五个机制：字段发现、类型规划、坐标缓存、掩码切片、顺序拼接。

① 先发现字段，再统一列与 dtype

每个文件的实际字段→显式 columns 或实际并集→检查缺失 / 形状→共同 dtype + 单位

sample_fields 收集根节点中形状恰好为 (N,) 的 dataset，包括目录未收录的字段；跳过 N、dt、info。目录中本批次的已知字段与身份字段如果存在但形状错误，会立即报错。

_columns_and_dtypes 在筛选行之前查看所有选中文件。因此，即使某个文件最终一行也没选中，它的字段缺失仍会触发 missing 规则。

情况行为
columns="all"按各文件实际字段遍历顺序取并集，保留首次出现；并非目录中全部定义，也不是文件字段的交集。
标准化的身份列由 identity 统一生成，不受普通测量列缺失填充逻辑支配。
某字段在多个文件类型不同np.result_type(*types) 规划共同类型；无法合并时退回 object。
已知字段缺失且允许填充追加可表示 NaN 的候选类型：通常 float，非数值情况使用 object；整数列可能提升。
同名字段在批次间的非空单位冲突_units 抛出 InvalidArgumentError，不执行单位换算。

② 一次打开，坐标只加载一次

read_files 为每个唯一航次创建一个 _FileReader。其 source_coordinates 首次访问时读取实际存在的 flight、line、year、doy、tt 数组。

@cached_property 保存这些坐标及派生的 tt、lines、identity。同一文件的多条 Selection 共用这些结果；生命周期止于这一次读取。

mask() 无条件访问 identity，因此 raw 读取和空结果也必须通过坐标检查。

③ 掩码：每行一个“保留 / 丢弃”

mask = np.ones(N, dtype=bool)
mask &= np.isin(line, requested_lines)
mask &= values >= start
mask &= values < stop

只执行实际提供的条件。多条航线内部是“或”，航线与时间条件之间是“且”。所有判断都依据文件坐标，不访问 segments 表。

这里是简化伪代码；真实实现会区分 tt / time，并跳过开放边界。

④ _runs：将离散命中行合并为连续读取区间

例如，掩码选择了第 1、2、5、7、8 行。连续行组成一段，可以直接用 HDF5 切片读取。

012345678
flatnonzero → [1, 2, 5, 7, 8]→diff → [1, 3, 2, 1]→[(1, 3), (5, 6), (7, 9)]
# reader.py · _runs（核心原文）
indexes = np.flatnonzero(mask)
groups = np.split(indexes, np.flatnonzero(np.diff(indexes) != 1) + 1)
return [(int(group[0]), int(group[-1]) + 1) for group in groups]

第一个区间 [1:3] 正好读取源行 1、2。区间按源下标递增，因此拼接各段时保留文件顺序。空掩码由前置分支直接返回空列表。

为什么不是“只加载命中样本”的严格流式读取？

筛选前需要加载整份文件的身份坐标，构造长度 N 的掩码。测量字段随后按连续命中区间读取；最终各 DataFrame 仍全部拼接到内存。首用校验还必须计算整个文件的摘要。

若一个 Selection 有 N 行坐标、K 行命中、R 个连续区间、C 个测量列，那么掩码与 _runs 含有 O(N) 扫描，测量数据约读取 K×C 个值，并产生至多 R×C 次字段切片。首次格式化 line 还调用 np.unique，通常带来排序成本。实际耗时受 HDF5 的分块和存储方式影响。

批量读取复用坐标，但重叠查询的测量片段仍可能再次读取。这里的缓存并不是跨调用的数据表缓存。

⑤ 输出组装：列顺序与行顺序是两份独立约定

列

标准化模式先插入六个身份列，再按请求顺序添加其他列，身份列不会重复。raw 模式只添加请求的源字段；缺失仍按 missing 规则处理。

行

每条查询先保持源文件顺序，再按查询顺序 pd.concat(..., ignore_index=True, sort=False)。输出重新建立从 0 开始的索引，保留重叠样本。

所有类型在读取前规划，所以全空结果也有完整 schema（列名与类型）。empty="raise" 对每条 Selection 独立判定；任何一条为空都会中止整次调用。

inspect_file 和 FlightInfo：读取报告而非样本表

inspect_file 创建相同的 _FileReader，访问 identity 完成坐标检查，然后枚举实际字段，附加可查到的单位、说明、分组与来源。未知字段的说明留空。

FlightInfo 记录 flight、path、sample_count、dt、tt_range、fields。它是 frozen dataclass，但其中的 fields 是独立 DataFrame，可以由调用者修改；“对象属性不可重新赋值”并不等于“所有嵌套内容都不可变”。

源码：reader.py · _runs（L64）、_FileReader（L72）、_columns_and_dtypes（L197）、_units（L261）、read_files（L281）、inspect_file（L326）。

06

FileStore：先确定文件可信，再交给读取器

这里包含两类状态：磁盘中的数据文件，以及本实例记住的成功校验记录。

fetch 的分支，取决于目标文件是否存在

当前状态执行路径结果
文件已经存在直接进入 _verified_path，比较文件状态或重新校验。成功返回 Path；无需创建目录或锁。
文件缺失 + offline=True清掉旧校验记录，立即报错。DataUnavailableError。
文件缺失 + 允许下载创建目录 → 按文件加锁 → 锁内再检查 → 必要时下载 → 校验目标。成功后返回 Path。
已有文件损坏校验失败并报错；该调用不会进入缺文件下载分支。DataIntegrityError，成功记录不会保留。

第一层：文件字节与基本结构

  1. 确认是文件，并记录读取前的文件系统状态。
  2. 比较文件大小与 FileSpec.size_bytes。
  3. 以 1 MiB 为块计算 MD5，并与固定目录比较。
  4. 用 h5py 打开，调用 sample_count 检查 line/tt 形状及可选标量。
  5. 比较校验前后的状态，确认期间未改变。

verify_file 的校验范围不包含所有样本字段和身份值；这些检查在 reader 中继续完成。

第二层：样本形状与坐标语义

  1. sample_fields 发现一维字段，并拒绝已知字段的不合法形状。
  2. 检查身份整数可表示为 int64，flight 与目标航次一致。
  3. 检查 line 非负且有限，tt 有限，doy 与年份有效。
  4. 使用这些坐标筛选或形成检查报告。
  5. Dataset 在返回前调用 check_unchanged。

校验通过说明文件与清单及接口结构相符；测量数据的科学质量需要后续分析。

一次成功校验，何时可以复用？

_verified[path] = (FileSpec, file_state)

file_state 是 设备号、inode、大小、mtime_ns、ctime_ns 的五元组。只有同一个 FileStore 中，文件描述和这五项都相同时才复用成功记录。

首次使用 → 完整校验→状态未变 → 复用→状态变化 / recheck → 重验

fetch(..., recheck=True) 强制完整复查；新 Dataset 拥有独立记录。缓存条目在重验之前先删除，避免失败后仍误认为成功。这个机制依赖可观察的文件系统状态，并不等价于每次重新计算摘要。

首次下载为什么会计算两次摘要？

当前实现先在临时路径上调用 verify_file，确认下载内容完整，然后 replace 到目标。返回 fetch 后，_verified_path 发现目标路径没有本实例的成功记录，因而再次验证并记录目标状态。

这是当前控制流直接产生的行为。后续复用同一实例且文件状态不变时，不会重复这两次校验。

两个进程同时下载同一个航次，会发生什么？

阶段进程 A进程 B
开始发现目标缺失，取得该文件的 FileLock。发现目标缺失，等待同一把锁。
下载中写入 data_dir 下的临时目录，目标文件尚未发布。继续等待，锁等待上限 3600 秒。
校验完成临时文件验证通过，原子 replace 到最终路径，然后验证目标。尚未进入临界区。
A 退出锁返回已校验的路径。取得锁，重新检查目标已存在，直接自行校验。

因此，共享目录中的首个下载可以合并为一次网络请求，而每个进程仍维护各自的校验记录。临时文件在失败时由 TemporaryDirectory 清理；隐藏锁文件保留，以维持稳定的锁文件身份。

锁的边界：锁保护缺文件时的下载与发布，不覆盖后续全部读取。读取依靠前后状态检查检测修改；它不是一个能够阻止外部写入的文件快照。已有文件直接校验，因此也可从只读目录读取。

实现要求文件系统支持跨进程文件锁和同文件系统原子重命名；fallback_to_soft=False 禁用软锁回退。下载文件遵循正常文件创建时的 umask 与继承 ACL。

句柄何时打开、何时关闭？

verify_file 的 h5py.File 由 with 语句管理；read_files 使用 ExitStack 同时管理每个唯一航次的读取句柄；inspect_file 使用自己的 with。成功返回与异常退出都会关闭句柄。

“一次 read 每个文件打开一次”指读取阶段；首次文件验证另有短暂打开。跨调用留下的是校验记录，不保留 HDF5 句柄、_FileReader 或测量数组。

源码：storage.py · file_state（L18）、verify_file（L40）、FileStore（L61）、_download（L88）、fetch（L106）。

Catalog：给字节赋予含义，并隔离可变状态

v3.json 中有四张主要表

键当前规模 / 用途

加载一次原始目录，各实例深拷贝

importlib.resources→@cache _catalog_data→deepcopy → Catalog

原始 JSON 解析结果可缓存；每个 Catalog 拥有私有快照，同时建立 flight 和 (collection, field) 索引。

查询返回独立结果，连嵌套 notes 列表也深拷贝。调用者修改返回表格，不影响下一次查询或其他 Dataset。

公共查询的含义与返回值

Dataset 接口结果需要理解的约束
metadata排除四张大表后的发布信息字典包括 release、doi、record_id、来源等；深拷贝。
flights(collection=…)发布文件列表可按批次过滤，不检测本地文件存在性。
fields(flight=… / collection=…, group=…)字段定义表flight 解析为所属批次；flight 与 collection 互斥。
field_names(…)名称 tuple与 fields 查询一致，按首次出现去重。
field_groups(…)分组、说明、唯一字段数使用 groupby + nunique，避免跨批次同名重复计数。
sensors(…)传感器位置表属于文档说明，不读取文件中的测量值。
segments(flights=…)原始文档段落表航次参数仅决定包含哪些记录；保留目录行顺序和重复航线。

这些 Python 对象分别保存什么？

对象存储内容生命周期 / 约束
Dataset一个 Catalog + 一个 FileStore跨调用复用；公共配置属性只读，换配置需要新实例。
Selection规范化的 flight、lines、tt、time不可变条件对象；可以跨读取调用复用。
FileSpec文件清单中选出的八项固定属性frozen + slots；在目录、校验和读取之间传递文件约定。
_FileReader打开的句柄、字段引用、缓存坐标只存在于一次 read 或 inspect 中。
FlightInfo已经脱离句柄的检查报告可返回给调用者；fields 表格可编辑。
DataFrame.attrs来源、单位、条件及各查询行数记录本次读取；后续 pandas 操作不保证保留或更新它。
缓存有三种，为什么不能混为一谈？

进程内的目录缓存：@cache 避免重复解析同一发布的 JSON，Catalog 再通过深拷贝隔离实例。

实例内的校验缓存：FileStore._verified 记住文件是否通过验证，以及当时的状态；它不保存样本数据。

单次读取的坐标缓存：@cached_property 避免对同一文件的多条查询重复加载和转换坐标；调用结束后随读取器释放。

根据错误类型，定位失败的层次

预期的库错误共同继承 DatasetError；InvalidArgumentError 同时也是 ValueError。

错误典型触发优先检查
InvalidArgumentError航次类型错误、tt/time 冲突、raw 请求 time、标量作为样本列、跨批次单位冲突。参数组合和字段语义。
UnknownReleaseError请求包内不支持的发布；目前只接受 v3。release，而非安装包版本号。
UnknownFlightError合法整数航次未出现在发布目录。flights()。
UnknownFieldError字段名既不在目录、身份列约定，也不在所选文件实际字段中。拼写、fields()、inspect().fields。
MissingFieldError已知字段在某个选中文件缺失，且 missing="raise"。是否允许显式 NaN 填充。
NoDataError某条 Selection 没有命中，且 empty="raise"。条件、边界、实际样本覆盖。
DataUnavailableError离线缺文件、下载失败、无法访问目录或锁、锁超时。本地路径、网络与文件系统访问。
DataIntegrityError大小/MD5 不符，结构、坐标损坏，读文件出错，或过程中检测到变化。文件来源、完整性与是否被并发修改。

missing 与 empty 管理不同轴

默认显式允许
缺字段MissingFieldErrormissing="fill" → NaN
没有行NoDataErrorempty="allow" → 零行表

这两个开关均不会放宽未知名称、损坏字段或坐标检查。字段与类型规划发生在空查询判定之前。

“文件存在某节点”还不足以当作列

未知名称如果对应实际 HDF5 节点，但该节点不是一维样本字段，读取器会给出 InvalidArgumentError，提示通过 fetch 直接访问。

已知样本字段若存在但形状不对，则给出 DataIntegrityError。若某字段在一个文件是样本列、另一个文件中形状损坏，也不能用 fill 掩盖。

按读取顺序排查，避免误判谁“先报错”
  1. 构造 Selection：立即检查并规范化条件。
  2. Dataset.read：检查调用选项，解析所有航次。
  3. FileStore：保证各文件可用并通过基本校验。
  4. read_files：打开文件，检查字段形状，规划 columns/dtype/units。
  5. 逐条 mask：检查身份坐标，计算命中数，执行 empty 策略。
  6. 读取、拼接、关闭句柄；最后检查文件状态并附加来源。

因此，未知字段判断可能发生在下载之后；如果缺字段和空查询同时存在，字段错误通常先发生。不能只依据用户代码中参数书写顺序推断检查顺序。

源码：exceptions.py；字段相关分支位于 reader._columns_and_dtypes。

理解常见 Python 写法，降低阅读门槛
@property / 只读公开属性

dict.fromkeys / deepcopy
前者用于稳定去重；后者复制嵌套结构，防止返回值修改污染内部状态。

  1. 目录没有 custom_signal，但文件有一个长度 N 的同名一维数组？

  2. 只有 fields(flight=2005)，本地 data_dir 不存在？
    从所属批次目录返回定义，既不下载也不创建数据目录。
  3. 本地文件只改了一个数值，字节大小不变？
    正常文件系统状态变化会使缓存失效，再计算摘要并拒绝与清单不符的文件。
  4. 查询航线列表的顺序与源文件相反？
    np.isin 只判断成员关系，输出仍保持源文件行顺序。
  5. 目录日期与源 year/doy 不同，但源坐标合法？
    使用已有源字段。当前代码仅在这些字段缺失时使用目录日期，flight 则必须匹配文件约定。
  6. fetch 成功，但已知测量字段形状损坏？
    fetch 的基础校验可能通过；read/inspect 的 sample_fields 随后拒绝损坏结构。
