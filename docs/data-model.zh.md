# 数据模型

## 已发布的数据、来源说明与实验划分

本包固定使用 Zenodo **v3**，记录号 [`12723700`](https://zenodo.org/records/12723700)，包含 2020、2021 两个批次的 16 个航次文件。它们是航磁采集时序数据中已经公开发布的部分。上游文件名以 `_train.h5` 结尾，本包保留这些文件名及校验和。

三类信息各有职责：

| 信息 | 以什么为准 | 对应接口 |
| --- | --- | --- |
| 实际存在的样本和字段 | 校验通过的 HDF5 文件 | `inspect()`、`read()`、`fetch()` |
| 字段含义、传感器位置、文档描述的区间 | 发布附带的 readme | `fields()`、`sensors()`、`segments()` |
| 你的训练集、验证集、测试集 | 你的实验设计 | 显式的 `Selection` 和后续分析 |

`is_holdout` 表示上游对该段落写有 holdout 标记。Holdout 指预留用于评估，**不表示无效数据或“废数据”**。无论该值为 `True` 还是 `False`，都不能证明对应样本存在于公开文件中。一段文档区间可能完全没有已发布样本；相同航线标签也可能出现在不同标记的段落中。样本覆盖以实际文件为准，训练和评估子集由实验中的显式选择确定。证据见[实际文件核验](data-audit.md)。

## 查询文档目录与检查实际文件

`flights()`、`fields()`、`field_names()`、`field_groups()`、`sensors()`、`segments()` 和 `metadata` 都可以离线使用。`fields`、`field_names`、`field_groups`、`sensors` 接受只能通过关键字指定的 `flight` 或 `collection` 范围，两者同时提供会报错。指定航次时，选取该航次所属批次的定义。`fields()`、`field_names()` 还接受 `group=`。

`fields()` 的每一行对应一个批次中的一个字段，包含 `collection`、`name`、`units`、`description`、`group`、`notes`、`source_url`。不限定批次时，同名字段可能出现两次。`field_names()` 返回按首次出现顺序去重的名称元组。`field_groups()` 返回真正的分组摘要，包含 `group`、`description`、`field_count`；数量指所选范围内不重复的字段名数量。

`segments(flights=None)` 保留 readme 中的起止数值，不替来源文档假定统一的端点约定。每行记录航次、段落序号、航线标签、起止秒数、说明、`is_holdout` 和来源链接。`segments([1004, 2005])` 可以限制航次。段落序号用于区分重复航线标签；这些行不会自动转换成样本过滤条件。

`inspect(flight)` 访问经过校验的真实文件，返回 `FlightInfo`：

| 属性 | 含义 |
| --- | --- |
| `flight`、`path` | 航次编号和校验通过的本地文件路径 |
| `sample_count` | 实际样本数 |
| `dt` | 文件声明的采样间隔，单位秒；没有则为 `None` |
| `tt_range` | 实际最小、最大值，两端都是已有观测；文件为空时为 `None` |
| `fields` | 实际存在的一维样本字段，附数据类型和可获得的文档说明 |

检查结果也包含文档未记录、但文件确实存在的样本字段。例如，2020 字段说明定义了 99 个字段，而核验的 Flt1004 只有 96 个；缺少 `year`、`doy`、`mag_6_uc`。查询文档与检查文件回答的是不同问题。

`Dataset` 的内部目录不作为公共对象暴露。返回的元数据字典和表格都是独立副本，包括嵌套的说明列表；修改它们不会影响下一次查询或其他实例。配置（`release`、`data_dir`、`offline`、`progress`）只读，要换配置就创建另一个实例。检查报告中的字段表也独立于内部状态。

## 选择条件与排列顺序

`Selection` 创建后不可修改。只有 `flight` 可以使用位置参数，`lines`、`tt`、`time` 必须写参数名。`Selection.all(2005)` 和 `Selection(2005)` 都选择该文件中全部实际样本。

航线标签使用小数字符串并统一为两位小数；不接受浮点数、通配符或航线范围。重复的航线条件会去重。两种时间坐标都使用 `start <= value < stop`，允许一端开放，不接受无效或非有限数值的边界、不接受步长，两端都有时要求起点早于终点。`time` 与 `tt` 不能同时使用；航线可与其中任何一个组合。没有时区的绝对时间按 UTC 解释。

读取结果先保留查询顺序，再保留源文件行顺序。航线列表表示“属于哪些航线”，不表示重新排列文件。接口不会隐式排序、重采样、插值或去除重复样本。重叠查询保留重复行。不能根据声明的 `dt` 或文件的起止时间推断覆盖连续。

## 返回列、类型与错误

`read(..., columns=...)` 必须明确选择字段。单个字符串表示一个字段，`"all"` 表示所选文件实际样本字段的并集；有顺序的名称集合按首次出现顺序处理。标准化结果具有固定前缀：

| 列 | 类型与含义 |
| --- | --- |
| `flight` | `int64`，文件/航次编号 |
| `line` | pandas 字符串类型，统一格式的航线标签 |
| `year` | `int64`，UTC 年份 |
| `doy` | `int64`，一年中的第几天，从 1 开始 |
| `tt` | `float64`，源文件记录的午夜后秒数 |
| `time` | `datetime64[ns, UTC]`，由年、日及午夜后秒数组合得到 |

源文件缺少 `flight`、`year`、`doy` 时，根据固定目录中的航次信息补齐。已有身份字段必须有效，不会用默认值覆盖损坏的内容。`columns=[]` 只返回这六列；显式请求身份列也不会让它重复出现。

`raw=True` 只返回实际存储的字段，包括原始数字形式的航线标签，不生成派生列，但仍然执行查询过滤和完整性检查。原始模式不接受 `columns=[]` 或派生的 `time`；源文件缺少身份字段时遵守普通缺失字段规则。标量 `N`、`dt`、`info` 不属于样本列，需要用 `fetch()` 获取路径后直接访问 HDF5。

“缺失字段”指目录或同批其他文件中已知、但当前文件没有的字段。`missing="raise"` 报错；`missing="fill"` 填充 `NaN`。为了表示 `NaN`，整数测量列可能变成浮点数；多文件合并时也会使用共同的数据类型。未知名称即使启用填充也抛出 `UnknownFieldError`。已存在的已知样本字段若形状不正确，则抛出 `DataIntegrityError`，不会伪装成缺失。实际存在但未被文档收录的样本字段可正常读取，缺少的说明留空。不同批次对同名字段声明了冲突单位时抛出 `InvalidArgumentError`，不会猜测单位换算。

`empty="raise"` 对每一条空查询抛出 `NoDataError`。`empty="allow"` 允许空查询；整个结果为空也保留全部列和预先确定的类型。查询集合本身不能为空，否则属于参数错误。

## 结果元数据

`frame.attrs` 包含 `release`、`doi`、`record_id`、`raw`、`flights`、`units`、`selections`。每条查询记录标准化后的航次、航线、时间条件和 `row_count`，允许空查询时也会记录零行。绝对时间边界使用 ISO 时间字符串。这份元数据记录读取行为；任意后续 pandas 操作不保证会保留或更新它。

## 文件校验与资源生命周期

文件按需下载到 `data_dir`。一个 `Dataset` 首次使用文件前，会检查字节大小、MD5 校验和、HDF5 可读性、必要坐标的形状及声明的标量元数据。读取和检查文件时还会验证样本字段形状及坐标值。这些检查保证文件与固定发布版本一致、结构有效，不代表每个测量值在科学意义上都合格。

只有同一实例内，且文件的设备号、inode、大小、纳秒级修改时间及状态变更时间没有变化时，才复用校验成功的记录。文件变化后重新校验，失败结果不会缓存为成功。`fetch(..., recheck=True)` 强制复查；新实例独立校验。这不代表每次调用都重新计算摘要，也不承诺抵御能够伪造文件系统状态的攻击者。

一次读取中，每个航次使用一个 HDF5 读取句柄，每个源身份坐标只读取一次。首次校验另有短暂打开文件的过程。成功和异常路径都会关闭所有句柄，读取过程中检测到文件变化则拒绝返回结果。跨调用只保留校验记录，不保留文件句柄或测量数组。本地文件损坏会明确报错，不会静默替换。
